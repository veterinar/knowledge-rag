# Критерии: RSS-бенчи выходят из относительного перф-гейта (ошибка единиц)

SDD: class MEDIUM, mode bugfix. Слово владельца 28.08: «делай» на перф-срез
после 3-го ложного красного за сутки.

Замеренное основание (байты прочитаны): оба флаки-бенча —
`test_bench_orchestrator_idle_rss` и `test_bench_query_cache_5000_entries`
из `bench/test_bench_memory.py` — возвращают RSS-ДЕЛЬТУ В МЕГАБАЙТАХ
(`after - before` от `_real_rss_mb()`), не время. Гейт
`check_perf_regression.py` читает их медианы как секунды: floor 1.0 ms их
«не видит» (0.17 «s» > 0.001), относительный ±10% на 0.1–0.25 МБ при
GC-шуме даёт ±14–36% на no-op диффах — 5 ложных красных за двое суток
(файлы прогонов в SEM-7). Категориальная ошибка единиц, не шум порога.
Обе величины УЖЕ сторожатся: абсолютные ассерты в самих бенчах
(<50 МБ / <80 МБ) и Pillar 3 — Memory baseline.

## Критерий 1

В `scripts/check_perf_regression.py` вводится
`MEMORY_MB_BENCHES = {"test_bench_orchestrator_idle_rss",
"test_bench_query_cache_5000_entries"}` (имена — из bench-файла, основание —
этот документ). Пара из этого набора исключается из fail-вердикта и
печатается отдельным блоком
`[INFO] memory-delta benchmarks (MB, gated by their own asserts + Pillar 3):`
с медианами и подписью `MB`. Остальные пары (время в секундах) гейтятся как
прежде; floor и ±10% не меняются.

**Проверка**: юнит: пара с именем из набора и дельтой +40% → нет fail, есть
memory-info строка; пара вне набора с +16% → fail как раньше. RED на базе:
первый кейс валит гейт.

## Критерий 2

Сводка гейта дополняется строкой числа memory-исключённых пар. FAIL-формат
для временных пар не меняется.

## Не-цели

Сами бенчи и их абсолютные ассерты не меняются; Pillar 3 не трогается;
never-выдуманных порогов не вводится; утренний floor (cee58dd3) не
пересматривается — он о другом классе (суб-мс время) и работает.

## Дельта основания (ревью R1, воспроизведено байтами baseline)

Первичные байты `perf-baseline-v4.7.1.json` (воспроизведено контролёром): у
обоих бенчей `timer=perf_counter`, `extra_info={}`. Медиана pytest-benchmark
в bench-JSON — это СЕКУНДЫ wall-time функции `measure()`, а НЕ возвращённая
МБ-дельта: дельта RSS в JSON не пишется вовсе. Таким образом, исходная
запись выше («возвращают RSS-дельту в мегабайтах… гейт читает их медианы
как секунды») лгала о причинности — ошибка не категориального чтения единиц,
а в том, что wall-time RSS-замера (два `gc.collect` внутри) шумит ±14–36%
на no-op диффах и НЕ является предметом memory-бенчей. Предмет (RSS)
сторожат их собственные абсолютные ассерты (<50 МБ / <80 МБ) и Pillar 3 —
поэтому пары исключаются из относительного time-гейта. Действие (исключение)
верно и остаётся; печать и формулировки исправлены на честные: заголовок
`[INFO] memory-bench wall-times (seconds; …)`, значения с суффиксом `s`,
счётчик «Memory-bench wall-time pairs excluded from gate», константа
переименована в `MEMORY_BENCH_NAMES`. Расхождение фиксируется здесь, а не
стирается.
