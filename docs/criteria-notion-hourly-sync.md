Статус: SDD-контракт составлен 2026-09-05 по слову владельца («ежечасный планировщик, каждый час в
рабочем состоянии макбука, но не затратный, аккуратный, не раздутый кодом, не ломающийся»).

(launchd хоста + экспортёр vetpilot + мост + сборка поколения + перезапуск сервера); исполняемые байты —
GLM через Hermes в канале.

## Задача одной фразой

Каждый час, пока Mac не спит, один короткий процесс выгружает Notion в снимок вне репозитория, сравнивает
его с прошлым по содержанию (без строки провенанса), и только при реальном изменении пересобирает
корпус, строит поколение и перезапускает сервер; всё остальное время — ноль работы.

## Критерии приёмки

- **AC-S1 — планировщик launchd, не демон.** `LaunchAgent` `com.vetclub.notion-knowledge-sync` с
  `StartInterval` 3600 и без `KeepAlive`/`RunAtLoad`-цикла; во сне не работает, после пробуждения
  launchd запускает один раз (не «догоняет» пропущенные часы). Процесс живёт только на время прогона.
- **AC-S2 — один сценарий, одна ответственность.** `scripts/notion_knowledge_sync.sh` (POSIX sh или bash,
  ≤ ~120 строк, `set -euo pipefail`, без сети кроме вызова экспортёра): лок-файл против наложения
  (`flock`/`mkdir`-лок), шаги `export → normalize → diff → [bridge → build → restart] → receipt`.
- **AC-S3 — дёшево, когда нет изменений.** Сравнение снимков по содержанию: дайджест снимка **без**
  полей времени экспорта и `source_commit`; при равенстве — запись строки «без изменений» и выход;
  измерено на прогоне без изменений: < 60 с, без запуска сборки поколения.
- **AC-S4 — гейт хоста перед тяжёлой частью.** Сборка поколения запускается только при свободном диске
  ≥ 20 ГиБ и отсутствии другого прогона сборки (лок); иначе — пропуск с записью причины, следующий час
  повторит. Порог 20 ГиБ — из канона (host-gate), не новый.
- **AC-S5 — сервер подхватывает поколение.** После успешной сборки — `launchctl kickstart -k` сервера и
  проверка `get_index_stats.ready == true` и `generation_id == построенное` (HTTP к локальному серверу
  или CLI `status`); несовпадение — красная квитанция, откат указателя не делается автоматически
  (это операция владельца по runbook reseal).
- **AC-S6 — секрет не течёт.** Токен читается из owner-only файла (0600) внутри процесса; не пишется в
  лог, квитанцию, argv и plist; логи прогона — в owner-only каталог.
- **AC-S7 — квитанция на каждый прогон.** Одна строка JSONL: время, sha снимка до/после, «без
  изменений» или generation_id + receipt_sha256, длительность шагов, причина пропуска; хранится в
  `~/.local/share/vetclub-knowledge-rag/sync/receipts.jsonl`; последняя строка читается брифом.
- **AC-S8 — снимок в репозиторий — отдельно.** Ежечасный прогон **не коммитит** зеркало в vetpilot;
  коммит снимка (`knowledge/notion`) остаётся ручным шагом контролёра (правило «снимок в репозитории —
  не запись в источник»); сценарий печатает, отстал ли репозиторный снимок от текущего.
- **AC-S9 — RED/GREEN на стенде.** Прогон с подменённым снимком (одно изменённое поле) → сборка и
  перезапуск; прогон без изменений → ни сборки, ни перезапуска; прогон при занятом локе → пропуск с
  причиной; прогон при «диск < 20 ГиБ» (эмуляция через переменную окружения теста) → пропуск.
- **AC-S10 — установка обратима.** `install`/`uninstall` — две команды (`launchctl bootstrap/bootout`)
  с квитанцией; plist — шаблон в репозитории с подстановкой путей, установленный файл — в
  `~/Library/LaunchAgents`.

## RED — мутации

| мутация | что обязано покраснеть |
|---|---|
| убрать нормализацию `source_commit` перед дайджестом | AC-S3 — каждый час «изменение» и сборка |
| убрать лок | AC-S9 — два прогона строят одновременно |
| убрать kickstart | AC-S5 — `restart_required` после сборки |
| напечатать токен в лог (эмуляция) | AC-S6 — проба грепом по логу красная |

## Не-цели

- Экспорт дочернего журнала Claude (страница `3cf1809f…`) — расширение экспортёра vetpilot, отдельный срез.
- Автоматический откат поколения; обратная заливка в Notion; синхронизация Vault-части корпуса (у неё
  свой ритм — серия guarded writer + build).
- Горячая перезагрузка поколения внутри сервера и запуск по сокету — отдельный срез
  (`criteria-server-pointer-reload`, ещё не написан); этот срез закрывает разрыв перезапуском снаружи.
