# Критерии: floor для перф-гейта — микробенчи ниже порога информируют, не валят

SDD: class MEDIUM, mode bugfix (CI-гейт). Слово владельца «го» 28.08 на
пункт «floor для флаки-перф-гейта».

Замеренное основание (двое суток, логи прогонов PR#17/PR#19): гейт с
относительным порогом ±10% дважды ложно краснел на субмиллисекундных
микробенчах — `query_cache_5000` median 0.20→0.24 (+18.7%) на docs-only
диффе, затем 0.16→0.20 (+31%) и `orchestrator_idle_rss` 0.11→0.15
(+35.6%) на build-child-only диффе; оба rerun'а чисты. Собственный шум
раннера на этих величинах ±30–36%, при этом содержательные бенчи
(reindex ~5.6–6.6 ms) стабильны в единицах процентов. Порог-строка гейта:
«permanently red check умирает» (testing.md) — чинится scope, не
ослаблением утверждения.

## Критерий 1

В `scripts/check_perf_regression.py` вводится floor: пара бенчмарков, у
которой ОБЕ медианы (master и branch) ниже `MICRO_FLOOR_MS = 1.0`,
исключается из fail-вердикта и печатается отдельным блоком
`[INFO] sub-floor microbenchmarks (noise-dominated, not gated):` с теми же
цифрами. Пара, где ХОТЯ БЫ ОДНА медиана ≥ floor, гейтится как раньше
(рост 0.11→1.5 обязан валить). Значение 1.0 ms — производное от замера
выше: флаки-класс ≤0.24 ms, стабильный класс ≥5.6 ms; floor разделяет их
с запасом ≥4× в обе стороны (limits.md: derived from measured evidence,
замер назван здесь).

**Проверка**: юнит на компаратор с синтетикой: (0.11→0.15) → нет fail,
есть info-строка; (6.0→7.0, +16.7%) → fail как раньше; (0.11→1.5) →
fail (пересечение floor); (0.9→0.99, +10% ровно под floor обеими) → info.
RED на базе eb672a84: первый и четвёртый случаи валят гейт.

## Критерий 2

Порог и floor печатаются в сводке гейта рядом («Threshold: ±10%;
micro-floor: 1.0 ms»), чтобы читатель лога видел обе границы. Существующий
формат [FAIL]-блока для гейтящихся пар не меняется.

## Не-цели

Сами бенчмарки, их набор и workflow-джоб не меняются; ±10% для
надпороговых пар не трогается; label `skip-perf-gate` остаётся как был.
