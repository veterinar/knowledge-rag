# Критерии-гейт: query augmentation (rewrite | expand | decompose | none)

SDD: class LOW, mode contract-first. Слово владельца 28.08: «делай» на
дельту №2 («режимы query augmentation, включаемые только при доказанной
пользе»). Кода в этом срезе НЕТ намеренно — как в python-autotest:
критерии допуска пишутся до реализации, реализация — отдельный срез по
слову, только после сигнала.

Замеренное основание: recall сейчас одноступенчатый (запрос → FTS5/вектор
без переписывания); известный дефект выдачи один — smoke v1-6 (дубль
знания: один тезис в двух документах). Сверка SEM-32 уточнила диагноз:
это не недобор recall и не дефект корпуса, а неверный smoke-oracle, который
прибивал общий тезис к одному `file_id`. Role-aware пара кейсов исправляет
oracle без augmentation. Других измеренных недоборов recall на 28.08 нет —
поэтому дефолт `none` и гейт, а не реализация.

## Критерий 1 — сигнал до реализации

Режим допускается к реализации только при задокументированном сигнале:
конкретный запрос из живой работы, где текущий recall не вернул
существующий в корпусе документ (кейс воспроизводим: запрос, ожидаемый
doc-id, фактическая выдача). Сигнал фиксируется новым кейсом в
`docs/runbooks/reseal-smoke-cases.v1.json` ДО авторинга. «Полезно вообще»
сигналом не является.

## Критерий 2 — RED/GREEN на существующих приборах

Кандидат режима обязан показать: RED — сигнальный кейс красный на
`none` (текущее поведение); GREEN — тот же кейс зелёный с режимом; и
отсутствие регрессии: все прочие smoke-кейсы v1 зелёные, перф-гейт
(`scripts/check_perf_regression.py`, floor + memory-units) зелёный на
том же прогоне. Оба мира меряются на одном корпусе одного поколения.

## Критерий 3 — none остаётся дефолтом

Режим включается только явным параметром запроса или конфигом с
провенансом (кто и когда включил, на каком основании); молчаливый
дефолт — всегда `none`. Проба: конфиг без поля режима → поведение
байт-в-байт равно текущему (дифф выдачи на smoke-наборе пуст).

## Критерий 4 — цена названа до включения

Каждый режим несёт измеренную цену: добавленная латентность на
smoke-наборе (медиана, тем же прибором, что перф-floor) и добавленные
вызовы модели (счётчик). Включение режима, чья цена не измерена, —
нарушение гейта (limits.md: число без источника не существует).

## Вне области

- Реализация любого из режимов.
- Изменения chunking/parent-retrieval (отдельная дельта №3, закрыта
  клиентским паттерном в скилле context-engineering).
- Автоматический выбор режима моделью.
